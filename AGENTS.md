# AGENTS.md

Agent reference for `portfolio-v9`.
This is a Vite + React + TypeScript app with Tailwind, Jotai, and Vitest.
Use `pnpm` only (`packageManager` is pinned in `package.json`).

## Runtime and tooling snapshot
- Node-based frontend app, ESM (`"type": "module"`).
- Bundler: Vite 8 (Rolldown).
- Styling: Tailwind CSS v4.
- State: Jotai + local React state/reducers.
- Testing: Vitest (`happy-dom`) + Testing Library.
- Lint/format: Biome, extended from `ultracite` presets.

## Canvas ownership and regression gates
- `initialItems` is a mount-time scene baseline. Parent rerenders do not reload it; use a new React `key` to replace a scene. Reset returns to that baseline.
- `use-canvas-state` owns committed item and viewport state; `use-canvas-viewport` owns the live transform, pending animation frames and settled commits (including reset and momentum).
- `use-canvas-interactions` owns activation/close commands, stack pages and return positions. Canvas owns local documents; the persistent route session owns article selection. Background interaction locks derive from both and from canvas visibility.
- Bind item IDs at `CanvasItemRenderer`, not in persistent callback maps. Callbacks must observe the latest configuration.
- Shared fan/swag geometry and fun-stack dimensions live in `src/lib/card-layout.ts`; renderers and auto-pan must use the same definitions.
- Measure untransformed border-box dimensions (`ResizeObserver.borderBoxSize`, falling back to `offsetHeight`), not transformed screen bounds. Fun-project detail offsets follow actual heights; allow only one settled-layout auto-pan refinement per expansion, cancelled by user input, resize, reset, close or another activation.
- Canvas viewport containers use `overflow: clip`, not `hidden`: native focus scrolling must not create a second coordinate offset outside the transform controller. Keep the keyboard-activated oversized-collection anchor regression.
- Canvas coordinates start at the top-left; keep `centerOnInit` disabled and explicitly override the transform library's `fit-content` dimensions with `!w-full !h-full`. Its injected CSS can otherwise override layered Tailwind utilities in development and center a zero-sized scene at half the viewport.
- Screen-dependent layout lives in `src/lib/canvas-layout.ts`. `App` picks the layout and scene once at mount from `window.innerWidth` (below 640px is compact) and provides it through `CanvasEnvironmentContext`; never re-derive it per render, because the scene positions and the reveal rules must agree. Desktop values are the original constants (`EXPAND_MAX_PER_ROW`, `SWAG_LAYOUT`, `FUN_STACK_LAYOUT`), so desktop geometry is unchanged. Compact reveals one column (`stackColumns: 1`, two smaller swag columns, fun-project cards as wide as the screen) and `src/lib/auto-pan.ts` slides the camera onto that content, pinned to the top, instead of centering cover plus content. Compact scene positions come from `src/scenes/compact-scene.ts`, which re-flows the desktop scene into one column and narrows project cards that would not fit.
- Touch input: coarse pointers pan from anywhere (`panning.excluded` is empty, the wrapper is `touch-none`) and cards are not draggable there, so a swipe never lifts the card under it. A long-press pickup was tried and dropped: Chromium can deliver the first touchmove hundreds of milliseconds late, and a hold timer then beats a slow swipe. `useIgnoreSyntheticMouseEvents` drops the mousedown/mouseup replayed after a tap, because react-zoom-pan-pinch listens for mousedown on `window` and cancels camera animations. `touchcancel` is forwarded to the library, which only listens for touchend. Touch has no Escape or hover: a Close button appears while a stack or the focused laptop is open, and swag labels and sticker notes open on tap. Hit-test stickers by rect, as the hover tooltip does; the base image swallows DOM hit-testing.
- The compact camera is bounded by `src/lib/pan-bounds.ts`: sideways panning is locked (`lockAxisX`) except around the focused laptop, and `useCanvasViewport` clamps drags and momentum to the resting scene, the opened item's content box (`getExpandedContentBox` in `auto-pan.ts`, using the measured fun-project height), which keeps `CLOSE_BUTTON_CLEARANCE_PX` below it so the last lines scroll clear of the fixed Close pill or the enlarged laptop. Our own `panTo` moves skip the clamp while `instance.isAnimating`, and end inside the bounds by construction because reveal targets and bounds share the same box. Desktop layouts return no bounds and keep free panning.
- The compact layout does not render `CanvasControls` (playground, reset): the camera is bounded and cards are not draggable there, so there is nothing to reset. Phone e2e must not rely on the reset button.
- Control buttons grow to 44px on coarse pointers via `pointer-coarse:`; do not change their desktop size, the visual baselines include them.
- The canvas controls are a liquid toolbar (`src/components/toolbar/`, ported from the city project's design system): `liquid-gooey` merges the button groups and the playground panel into one goo surface with one shadow, the panel opens as a blob that morphs out of its trigger (spring easings compiled to CSS `linear()` in `spring-css.ts`), and one tooltip glides between buttons on the panel side. The goo canvas is a fixed reserve (`PAD_RESERVE_*` in `toolbar-geometry.ts`) sized for every panel, because liquid-gooey's SVG filter does not follow later growth, and its reach toward the screen edges is capped so the filter never spans the viewport. Panels draw no surface of their own; the blob does.
- Scene entrance: `useCanvasEntrance` mounts the scene hidden (`data-entrance="waiting"` on the canvas container), waits for fonts and decoded on-screen images (capped at 1.2s) plus an idle moment, then plays one wave from the top-left (`playing`) and drops the attribute when settled. Delays come from `src/lib/canvas-entrance.ts`; the motion is CSS keyframes in `src/index.css` on the `.canvas-entrance-item` wrapper that `CanvasItemRenderer` puts around each item, opacity and transform only, so it runs on the compositor. Items themselves mount at rest (`initial={false}`); follow-up details (folder papers, fun-project icons) read `useItemEntrance` and start once their item has landed. The default desk lamp switches on during `waiting` when the WebGPU adapter answers in time, so cards rise already lit; a later answer waits for `done`, because WebGPU setup mid-wave drops frames. While `useDeskLampProbe` is pending, or the lamp is coming on and `DeskLampRoom` has not reported its first shadows (`onShadowsCast`), the entrance stays `waiting` (still within the 1.2s cap): under the lamp cards have no stylesheet shadows, so starting earlier made every shadow appear at once after the wave. `hideLampScene` makes those first shadows land without easing, and when the hold lifts they ease for 400ms to wherever the lamp has moved. While `playing`, `holdLampShadows` freezes the lamp's DOM shadows (they ride up inside the wrapper); rewriting filters per frame would re-raster the rising cards. The root's `PortfolioLoading` stays behind the transparent canvas from first paint until the canvas reports its entrance through `onCanvasEntrance`; it is visually empty unless loading passes three seconds, when a plain `SpinnerIcon` fades in. Lamp-on work stays out of the first load: `DeskLampRoom` (dimmed room and shadow loop) is lazy, shadows ease from the stylesheet's to the lamp's while the room dims, and WebGPU pipelines are built with `createRenderPipelineAsync`, because synchronous compiles stall compositing. Browser specs that read card geometry or interact right after load call `waitForCanvasEntrance` from `e2e/fixtures.ts`.
- Project images use viewport-aware native lazy loading; retain eager loading for primary covers. Videos must not start just because hidden measurement content mounts.
- Covers and project screenshots are encoded for 3x screens. Each image in `src/assets/{covers,mintlify,mosaic,rbc,wealthsimple}` has a `-2x.webp` sibling sized for its card at 2x (480px covers, 720px screenshots), served to 1x/2x screens through `srcset` by `src/cards/responsive-image.ts`. Create one for every new image there with `cwebp -q 82 -m 6 -sharp_yuv -resize <480|720> 0 <name>.webp -o <name>-2x.webp`; `src/cards/responsive-image.test.ts` fails when a card image lacks it.
- Optional chunks that the first view does not need (swag tooltip labels) wait for `whenPageIdle` (`src/hooks/page-idle.ts`: window load, then idle) so they never compete with first-view images. Swag labels must still be loaded and rendered before the first expansion; otherwise 100+ items suspend at once when the collection opens. The markdown renderer is first-view content (the About card), so it is not deferred.
- Code blocks use `react-shiki/core` with the pure-JS regex engine and per-language grammar imports (`src/components/code-highlighter.tsx`). Do not switch back to the full `react-shiki` bundle: it fetches a ~230 KB gzip WebAssembly engine and emits hundreds of grammar chunks. Add a grammar to `GRAMMARS` when content needs a new language; unknown languages render as plain text.
- CI runs formatting, lint, coverage, production build, initial-JS budget, Chromium desktop/touch, WebKit desktop/iPhone, Firefox desktop, and Chromium visual regressions on Ubuntu 24.04. Unit coverage includes the Canvas and group integration surfaces.
- CI retries browser failures once for diagnostics but still fails on flaky tests. Async-layout assertions must check eventual geometry, not assume a quiet sample means lazy media has finished loading.
- CI runs browser specs on one worker: parallel browsers on the hosted runner drop animation sampling to a few frames per second. Even then, hosted WebKit and Firefox draw only ~4 frames per paper projection, so assertions that need a mid-motion frame (or a pointer aimed at a moving card) run on Chromium only; per-frame geometry checks run everywhere. Pull pre-recorded frame data from the `paper-projection-frames` trace attachment before loosening a check.
- Visual tests pin the actual Inter (normal/italic) and Playpen Sans fonts, seed content ordering before app modules, and wait for assets plus JS-driven motion. Six baseline states cover initial canvas, GitHub/fun/Swag expansion, About and Reset. Generate candidates via CI's `generate_visual_baselines=true` dispatch input, review the artifact, then explicitly commit accepted PNGs. Normal CI must fail on missing or changed snapshots; never auto-approve references or widen tolerances to hide regressions.
- Initial Linux baselines were generated by GitHub Actions run `36240719056` from source `9a02faa` with Playwright 1.63.0, then visually inspected before committing.
- WebKit iPhone emulation does not support Playwright mouse-wheel injection; wheel-dependent scenarios are explicitly skipped there, and CDP touch cancellation is Chromium-only. Device emulation is not a substitute for real iPhone/Safari gestures, backgrounding and GPU testing.
- Per-route JS budgets follow static imports in `dist/client/.vite/manifest.json`: 950 KB raw and 300 KB gzip for Article and Not found, and 990 KB raw and 330 KB gzip for Home (raised from 300 KB for the socials keyboard's lamp-only third, mechanical stop and its tick marks, and the lamp hooks of the lit cards, then for the lit surfaces' adaptive redraw queue and the lamp's playground settings, then by ~19 KB gzip for `liquid-gooey` in the canvas controls, then to 990 KB raw and 330 KB gzip for the lamp shadow hand-offs the cards render (shadow canvases, outline sprites) with room for further lamp work; the lit keyboard, email card and badge load lazily with the lamp). Home also includes its lazily mounted canvas App, while article bodies, highlighter grammars and media remain excluded. Match vendor package paths precisely so lazy highlighter dependencies do not become eager. Do not raise the budget to hide a regression; document intentional product-driven changes.
- Phone and gesture coverage is `e2e/touch.spec.ts`: it runs on the `touch` and `webkit-iphone` projects only, and its CDP swipe cases are Chromium-only. Keep the test that taps must not surface mouse presses; it fails when the echo guard is removed.
- Browser specs live in `e2e/`; Vitest runs colocated `src/**/*.test.{ts,tsx}` and `tools/**/*.test.ts`, not browser/performance specs. Measure frame time and media transfer separately before adding virtualization.
- The isolated performance suite lives in `perf/`, with JSON and text reports in ignored `perf/results/`. It retains real animations and reports observed interaction signals, RAF intervals, long frames, network transfer, and DOM/heap trends. These are lab measurements, not INP, display FPS, or proof of memory leaks. Reports do not impose hard timing gates, and no instrumentation is included in production.
- The lockfile resolves Base UI to 1.8.0: 1.1.0's Slider incorrectly reads the global `event`. Keep the real keyboard-slider regression when updating this dependency.

## Articles and static rendering
- Requires Node >=22.22.0; use pnpm exclusively.
- React Router Framework Mode uses Vite with `ssr: false`; published articles are prerendered as static HTML.
- Writing is accessed from its canvas folder; there is no `/writing` index page. Article and error-page return links point to `/`.
- Add articles by adding a directory; keep localized titles consistent with available MDX files.
- Articles, About and the resume share one reading system in `src/index.css`, measured from Apple Newsroom: `.reader-paper` (24px phone gutter with the reader's 20px viewport padding, 56px inset from 640px), `.reader-column` (34em measure, 17px body, 19px from 1024px), `.reader-title`, `.reader-meta` and `.article-prose`. Chinese keeps the sizes with taller line heights via `:lang(zh)`. About renders through `MarkdownRenderer`'s `prose` mode; the default mode stays the compact project-card styling. Secondary text in documents uses `text-foreground1/65`, since `foreground2` fails contrast for reading copy. The standalone article page uses the same `px-5` viewport padding as `ReaderShell`, so both match the width `ReaderPaperLayout` measures.
- Use h2-h6 inside MDX; ArticleSheet supplies the h1. Imports of local images preserve dimensions and use Vite hashing.
- Content generation validates metadata/MDX, creates Unicode heading IDs and bounded previews, and excludes drafts from client loaders, sitemap and share images.
- Heading metadata remains in Node validation only; client article metadata (`src/content/generated/catalogue.ts`, loaded by every route) contains titles, dates and reading times. Bounded card previews and their image imports are generated separately in `src/content/generated/previews.ts`, imported only by the canvas article card, so article and 404 pages do not download them.
- Card previews use ArticlePaper and article-prose at the reader's responsive width, then scale the entire paper into the fixed card frame. Keep typography and spacing shared; never recreate a separate card layout. ReaderPaperLayout measures the available width with the same reserved scrollbar gutter as the article reader; observers measure untransformed paper dimensions independently of canvas zoom. Article projections use the actual paper's aspect ratio and clip only during layout motion.
- Previews preserve a static prefix with inline formatting, headings, separators, lists, quotes and controlled local images, capped at 16 blocks, 4,000 Unicode characters and 256 nodes. Static `ArticleImage` imports (including aliases) support local image assets, literal dimensions and literal alt/title/className; dynamic props and unsupported MDX/media stop the prefix instead of skipping visible content. Image URLs are generated as deduplicated Vite `?no-inline` imports, never inline asset data or MDX imports. Reuse ArticleImage's dimensions and styling; reserve the exact aspect ratio before loading. One IntersectionObserver per preview assigns image URLs only when they intersect the clipped viewport, because native lazy loading alone can prefetch hidden images in WebKit. Keep native lazy/async loading, card-height clipping and the bottom fade. Canvas previews never load full MDX.
- Motion re-measures every shared-layout node in the canvas's `LayoutGroup` whenever any one of them updates. Tucked cards in a closed folder therefore carry no `layoutId` (they cannot be opened); it mounts with the card, via `key`, when the folder opens. Giving them an id again makes their papers jump twice while the folder closes (`e2e/folder-collapse.spec.ts`). Hover peeks are ignored for 700ms after a toggle, because the camera slides covers under and away from a still pointer.
- Document repulsion takes priority over folder repulsion. Nested article centers come from the visible page's fan layout, including rotation and arc offsets. Repel the cover and sibling cards separately while keeping the active article's shared-layout anchor fixed.
- Keep heavy reader content and canvas scenes out of the root's static import graph. The root renders a hydration-safe canvas placeholder.
- Article clientLoader prepares the browser MDX module before navigation commits; the server loader prepares static rendering separately. Reuse resolved modules synchronously so a Suspense fallback cannot replace the card's body during shared layout motion.
- Under the lamp the fun-project icons become WebGPU keycaps (`lit-keycaps.tsx`, `keycaps-shader.wgsl`), mounted as soon as the lamp is on. Each cap grows in with its DOM icon's pop: `popAt` reads the scale Motion writes inline on the icon, and the shader scales that cap's rounded edges (a scale of 0 is not drawn), so a card that rises lit never shows the pictures first. Prints (`src/assets/fun-projects/glyphs`, 288px squares without the cap) and plastics live in `src/scenes/data/fun-project-keycaps.ts`, loaded through the card content's `loadKeycaps` only when the lamp is on. Until the caps draw, or without WebGPU, each DOM icon casts its own lamp shadow, as high as the pointer lifts it, and a `lamp-sheen` glint. Lit surfaces, the MacBook included, share a redraw queue in `lit-surface.ts`: its per-frame budget grows while frames arrive on time and halves after a late one (a fixed four left each folder relit every fifth frame), but only on frames that used all of it: a budget left to climb while the lamp rested redrew every surface on the first fast sweep, stalled the GPU and collapsed to the minimum for a third of a second. The budget counts backing pixels (each surface's canvases, overhang included; `canvases` on `runLitSurface`), not surfaces: counted in surfaces, the 15 prints of an opening folder all fell stale at once within the budget a sweep had left, twice the pixels a frame could draw, and three or four frames in a row ran late. A draw into a new or resized backing store counts `ALLOCATION_COST` (2x); lamp shadow canvases skip the queue but charge their pixels with `chargeLitPixels`. Each late frame records the budget it ran at, and growth (2% a frame) drops to 0.25% within 85% of it, so a saturated lamp probes past its ceiling every few seconds. Opening the Wealthsimple folder went from 3-4 late frames to 0-1 cold and 1-2 right after a sweep. Turns go to the surface whose lighting is most visibly stale, so those under the pointer redraw first; tucked prints in a closed folder (`covered`, prominence 0) keep their last frame however the lamp moves and are relit when it opens, which freed a quarter of the pixels redrawn in a fast sweep; ranking waiting surfaces up by how long they waited took turns from those under the pointer and made their shadows step. Surfaces whose own parts move (a lifting cap, a pressed key) jump the queue. The queue's halving tracks real capacity: on an Apple GPU at 2x about 4.5 million redrawn canvas pixels a frame, ~11 draws. Never shrinking it doubled draws and dropped to ~34fps. The cost is per redrawn pixel (texture allocation, present, compositing), not per canvas or per shader instruction: at half resolution the same machine redrew 25 canvases a frame with no late frames, removing ten canvases did not help, and tripling draw calls barely mattered. So surfaces whose detail is soft (papers, labels, prints, folder covers) pass `motionScale: 0.5`: while the lamp moves faster than ~240px/s they redraw at half resolution, never below one backing pixel per CSS pixel, and restore full resolution 150ms after it slows. That cut paper-shadow lag over 1px from ~27% to ~4% of frames while circling the keycaps, with half the late frames. Keycaps, the laptop, keyboard, email and badge draw sharp prints and keep full resolution. Measure in a visible browser with no other lamp pages open; competing GPU work made an earlier run look canvas-bound. `subscribeLamp` listeners read layout when called and return their DOM writes, which run after every listener has read; writing inline forces a style recalculation per listener. DOM casters (`data-lamp-shadow`) take only the lamp's single `drop-shadow` in their per-frame filter; casters whose outline is their own rounded box (papers, prints, pills) add `data-lamp-contact` for a contact shadow written as a `box-shadow`, which changes only with lift. While a contact caster flies (over 120 canvas px/s, back under 30), the lamp writes its shadow as an equal box-shadow instead (blur doubled: drop-shadow's blur is a standard deviation) and rewrites it only after a 3px step: the compositor re-blurs a drop-shadow filter every frame its caster scales or rotates, and Wealthsimple's 15 prints and captions dropped about one frame in eight opening or closing, even with the filters held still. While the lamp is on every caster carries `will-change: filter` (added to any transform hint it already has): painted in place, each per-frame drop-shadow rewrite re-rasterized the card under it, and a lamp sweep over an open folder dropped one frame in five with the lit surfaces left a fifth of their redraw capacity; as layers the GPU only re-blurs cached pixels. Filters are rewritten only after a 0.5 screen px change. Prints and article papers go further: `PaperLighting castsShadow` puts a WebGPU canvas behind the caster (`lit-shadow.ts`, `shadow-shader.wgsl`) that draws its lamp shadow in closed form (erf of the rounded box's distance, matching drop-shadow's Gaussian) at 0.5 backing px per screen px, outside the redraw queue. The caster claims its shadow with `claimLampShadow`; the lamp then leaves its filter off and hands the canvas the shadow it worked out, except while the caster has a transform of its own (a layout animation), hidden or tucked in a closed folder, when the filter draws it again. On an M3 at 2x a fast sweep over the open Wealthsimple folder went from ~49fps with 20% late frames and 0.8 Mpx of lit-surface redraws a frame to ~58fps, 3% late (the budget's own probing) and ~3.9 Mpx. Casters that are not boxes behind which a canvas can sit (swag stickers, folder covers and backs, fun-project detail cards) get a `LampSprite` canvas inside the caster at `-z-10`, whose `outline` is the caster's image alpha (`"image"`), the rounded border box of its first other child (`"box"`), or an SVG path over its box (folder covers: `FOLDER_SHAPE_PATH`); tucked prints keep their shadow canvas in a closed folder. Every frame the lamp moves the compositor redraws the whole desk and re-blurs every filter on screen, changed or not, so with these no filter remains on screen at rest; under a fixed extra GPU load standing in for a weaker GPU, late frames fell from 39-62% to 13-24% across home and an open folder. For stickers, `lit-sprite.ts` draws the image's outline blurred once with a 2D canvas `shadowBlur` (WebKit ignores the context's `filter`) at 0.5 backing px per screen px, claims the shadow with `{ inside: true, ready: false }`, and then only moves and fades the bitmap, which the compositor does without blurring. The lamp hands an unready claim its shadow only once the sticker rests (a flying sticker blurs more), and uses the filter again whenever it is lifted past `RESTING_LIFT` (hover, flight). Bitmaps are drawn four a frame across all stickers (a hundred in one frame held it for 100 ms; six a frame still dropped two) and again only after a 20% zoom or 35% blur drift (the shadow's length alone varies it 28%). Layout for them is read in the lamp's read phase. An open collection's lamp sweep went from ~76% GPU to ~55% with no more late frames on opening. Lamp layers blend normally, never with `mix-blend-mode`, except the folder covers' colored light: a blend mode makes the compositor render its whole group into an extra pass whenever anything in it changes (about 37 passes a frame dropped to 15). The paper shade draws black at `1 - tone` (exactly multiplying by the grey tone), the gloss draws premultiplied light as opaque as its brightest channel (screening, within a few percent warmer over white), sheens are white at an opacity (exactly screening). The room overlay (`room-gradient.ts`) darkens by a third of the way from the tone's darkest channel to its brightest and adds back half of each channel's excess, within two levels of multiplying; under the lamp the body is white, because the page background never took part in the old multiply, so the bare desk showed the tone itself. That took an open folder's fast sweep from 2% late frames to none and the lit surfaces from 4.3 to 5.1 Mpx a frame. Heavier casters deepen their shadow with `data-lamp-depth` (`LAMP_DEPTH`, folder covers 1.6) rather than more lift: a higher caster spreads the same darkness thinner, so its shadow reads lighter next to it. A second drop-shadow chained into the filter doubled its raster cost: fast sweeps dropped every fifth frame, which collapsed the WebGPU draw budget. Measure frame pacing in a visible browser; headless Chrome does not present frames and hid that cost.
- The desk lamp runs in desktop Chromium and desktop Safari (`isDeskLampSupported`: exact `Chromium` client-hint brand, not mobile, not Android; or, without client hints, a Mac WebKit user agent with no touch points, which rules out iPads asking for desktop sites). Firefox stays off. `?lamp=force` skips the browser check (WebGPU and the adapter probe still decide) for comparing it elsewhere. Playwright's WebKit is not a stand-in for Safari here: it kept SVG masks that Safari drops, and it runs lamp mode at ~12fps while real Safari is smooth, so confirm Safari rendering and performance in Safari itself. WebKit keeps a 2D context's `filter` and reads it back but never blurs, so the folder relief and seam blur through `drawBlurred` in `folder-renderer.ts`, which probes once and falls back to an offset shadow (`shadowBlur` 2σ = Gaussian σ); never set `context.filter` directly for lit textures. Safari's canvas also drops SVG masks when it rasterizes a logo, so a cover whose logo SVG uses `<mask>` gives the lamp a bitmap through `litLogo` (`src/assets/logos/mintlify-lit.webp`): drawn by Chrome from the SVG at 252px (84px × `LOGO_DENSITY`), then `cwebp -q 90 -alpha_q 100 -m 6 -sharp_yuv`. resvg renders that logo's glass wrongly, so do not regenerate it with resvg; redo it when the SVG changes.
- The playground's Light tab (first, and only while the lamp is on) edits `lampConfigAtom`: lamp height, pool size and room dimming. The lamp's follow rate is the fixed `LAMP_FOLLOW_RATE`. `DeskLampRoom` copies it into `desk-lamp.ts` with `setLampConfig`, and every lamp listener reads `getLampConfig()` each frame instead of constants. Defaults (`src/lib/lamp-config.ts`) reproduce the designed lighting. The room gradient lives in `src/lib/room-gradient.ts`, outside the first-load graph.
- The Tiny Toronto street map (`src/cards/streetmap/`, kind `streetmap`, `toggle-focus`) rests as its cover image (`src/assets/streetmap/cover.webp`, 3x, with a 2x sibling) and mounts the lazy `streetmap-sheet.tsx` chunk when focused. The fold is pure geometry in `src/lib/map-fold.ts` (16 panels, open springs that continue from any pose, eased close); the sheet writes their `matrix3d` per frame, shades each face with a CSS gradient and draws its own projected shadow on a 2D canvas, so `SingleCardItem` gives it no drop-shadow or lamp caster. On a phone held upright (compact layout, taller than wide) the open sheet turns a quarter as it grows and its print is laid out tall (`PORTRAIT_PRINT` in `sheet-art.ts`, turned into sheet space through `toSheet`), so the map stands upright and fills the screen; the paper's shading is matte, with no specular hot spot, because a sharp gloss read as plastic. Phones open on `compactView`, wide screens on `view` (zoomed so the harbour is about a quarter of the frame). Folds are drawn by `drawCreases`: a wavering fibre hairline, a soft rounding band (light on mountain folds, shaded on valleys, alternating along the accordion) and ink cracks as fine streaks clustered by noise and near crossings; dashed or dotted wear read as a drawn rule. While the map is focused the canvas controls fade out (`isMapUnfolded` in `canvas.tsx`), so the open sheet fits the window with a small `FIT_MARGIN`. Sharpness: each panel face is its canvas alone, with its shade a sibling layer over it. A face holding canvas and shade together became one intermediate surface, which Chrome rasterizes at a fraction of the screen's resolution under a 3D transform (measured 177 against 1616 in Chrome), so the map read soft while moving and snapped sharp at rest; do not wrap them back together or flatten the resting sheet to 2D, which reintroduces that snap. The rows meet in one plane: `getPanelPlacements` lays the cross fold flat once it is within `CROSS_FLAT` of open, because Chrome splits faces that are nearly but not quite coplanar and draws the pieces a pixel off, and the front faces bleed across the cross crease with the other row's real pixels rather than repeated edges, so which coplanar row Chrome draws on top does not show; without both the cross crease visibly jumped as the open sheet settled. Headless bundled Chromium composites 3D in software and stays soft regardless: measure sharpness in Chrome. The map canvas is printed onto the sheet on whole device px (`printMap`), tiles are never coarser than the screen (`getTileLevel`) and are not tinted, washed or desaturated, which had made the map warmer and duller than the live site. The booklet lies square on desktop and turned `restTilt` (-5deg) in the phone column, where `NUDGE_X_PX` in `compact-scene.ts` shifts it right to read centred; the controls fade back 650ms after the map closes. The close's cross fold runs 0.52s on a sine ease: its edge swings more than twice as far as an accordion panel's, and on the cubic ease it snapped about three times faster. On the desk the booklet shows its folded stack peeking under the cover (`STACK_LAYERS`), a paper grain and rounded fold edges. It sizes itself to the window as it opens (registry `focusScale` stays unset, so compact pan bounds pin the camera to the booklet) and the camera returns 320ms after closing, so the map folds in place first. The map is live: `map-tiles.ts` draws Tiny Toronto's content-hashed tiles (index ported from the toronto viewer, `tile-index.ts`) with coarser stand-ins while sharp ones load, `src/lib/map-view.ts` holds the view math, and `sheet-art.ts` prints it onto the paper (multiplied into the paper, slightly desaturated, cyan plate out of register) under a fixed frame, grid and title block with a live scale bar. Drag pans with a fling, ctrl/⌘ + wheel, Safari gesture events and two-finger pinch zoom around the pointer, plain wheel pans, double-click zooms (Shift out), arrows and +/- work while open; the sheet stops wheel and touch propagation so the canvas stays still, and carries `no-drag` so clicks never toggle it. - The time machine (opened by the toy time machine on the desk, desktop only) is Mission Control for earlier portfolios, modelled as one camera over a row of same-size windows (`src/lib/time-machine.ts`): each window is the screen inset by `getWindowPadding` at its sides and top and by `bottomPadding` (that plus `CONTROLS_SPACE_PX`) below, where an open window's controls sit, laid out from the present into the past in world px, and the camera names the world point at the screen's centre plus a zoom. Closed is scale 1 on the present; the timeline zooms out with the present in the middle and earlier versions to its right, newest first, running off the edge; opening a version is scale 1 on its window. Moving between them only moves the camera, so neighbours slide along the row instead of fading over each other: on close the past slides off to the right. Two more animated values: `crop` turns the present from the whole screen into a window (its inset and corner radius grow with it, so corners round in continuously), and `push` shoves the windows beside the one nearest the camera further out while it is close, as the canvas's repulsion does. All five values spring on one `CAMERA_SPRING` (framer-motion `animate` on plain `motionValue`s), and one `frame.render` writer sets every transform and squircle `clip-path: path()` (`getSquirclePath`, superellipse exponent 4, 40px on screen at any zoom, drawn in element units as `WINDOW_RADIUS_PX / scale`); `corner-shape` cannot shape a clip. The canvas wrapper's clip is cleared at rest. The row scrolls natively: a transparent full-screen scroller (`data-time-machine-scroller`, vertical, sized to the row in screen px) covers the timeline and the camera follows its `scrollTop` one to one, so momentum, wheel smoothing, Safari's end bounce and clamping are the browser's own. Hand-rolled wheel handling was tried and dropped: choosing a spring or a 1:1 jump per event (by delta size) made trackpad flings and accelerated mouse wheels snap between the two, unbounded overscroll left a dead zone when reversing, and a passive listener could not stop Chrome's back-swipe. Sideways swipes are added to the scroller (`preventDefault`, which also blocks the history gesture); step buttons, arrow keys, keyboard focus and clicks on a cut-off window centre a window with `glideTo`, which springs `camera.x` on `CAMERA_SPRING` and writes the scroller's `scrollTop` each frame (`writtenTopRef` tells those writes from the user's scroll; the wheel stops a glide where it is). The browser's smooth `scrollTo` restarted from rest on every call, so quick presses felt sluggish; the spring keeps the camera's speed, so they add up, aimed from the glide's target (`getTimelineTarget`). Setting `scrollTop` from the stage (back from an open window) must leave `scrollRef` equal to it, so the scroll event does not cut the camera's flight short. Because the scroller covers the windows, it takes their pointer: clicks and hover hit-test with `getWindowAt`, and a click on a window the screen's edge cuts (`isWindowInView`) only scrolls it to the middle, while one wholly in view opens; the window buttons stay underneath for keyboard and assistive tech, so browser specs click by position. WebKit scrolls by whole pixels, so centring is only exact to about a pixel. Labels read "Now" and the version's month (`formatVersionDate`, `date` in `versions.ts`), with no hover or focus ring on the windows: keyboard focus lights the label instead. The room is flat dark grey from the first frame (`#323235`) and deepens into its vignette over `ROOM_FADE_MS`; fading the whole room in from transparent showed the desk's near-white first. Root owns it: `openTimeMachine` on the canvas session loads `src/components/time-machine/time-machine.tsx` (warmed on hover/focus by `warmTimeMachine`) and holds the component in state, not `React.lazy`, which suspended once even for a loaded chunk and held the first frame ~300ms behind Suspense's throttle. Opening sets `canvasVisible: false` so the canvas's interaction locks apply, `timeMachineOpen` so the canvas controls hide at once (the liquid toolbar's SVG goo filter does not follow the scale and smears), and makes the canvas wrapper `inert`. Closing, `onLanding` fires once the zoom passes 0.99 and clears `timeMachineOpen`, so the toolbar fades back while the spring's tail settles (about 650ms after the close starts, not after `onClosed`); its 650ms delay applies only after the street map (`toolbarHiddenBy` in `canvas.tsx`). The stage transforms the wrapper itself (imperative styles, restored on unmount), so the live canvas keeps its state; root re-renders would re-render the whole App, so do not drive the camera through React state. `pauseLamp` stops the lamp's listeners while the canvas is scaled: they measure in client px. Earlier versions are their own deployed sites (`versions.ts`): v8 at v8.rickyzhang.me, and portfolios that are no longer online as static copies in the separate `portfolio-archive` repository, served at `https://archive.rickyzhang.me/<id>/` (2018 Jekyll, 2019 Adobe Portfolio, May 2022 and Dec 2022 React builds; rebuilt from their old sources or scraped, with analytics removed, vendor scripts and fonts self-hosted, images as WebP and each SPA route given its own copy of `index.html`, since Pages rejects a `_redirects` rewrite to `index.html` as a loop). Each is shown as a screenshot (`node tools/capture-time-machine.ts <id>`, shot at an open window's size on 1440x900 at 2x; `TIME_MACHINE_ARCHIVE=http://localhost:<port>` shoots the archive from a local server before it is deployed) until a sandboxed iframe (mounted on hover/focus to preload, or on open) has loaded and its window has been opened and landed (`FRAME_REVEAL_AFTER_OPEN_MS`), when the page fades in over it: a load event can come before an old site paints, so a frame revealed on the timeline could show a white window. The screenshot stays under the frame, which has no background of its own (every version paints an opaque page): a cross-origin frame stepped onto after sitting off screen sometimes presented nothing for a while, and the frame's old white background showed as a blank window; the iframe is `inert` and covered by a button until its window opens. Escape steps back (open window, timeline, canvas) but cannot reach the page while focus is inside a cross-origin frame, so the padding and the close button also step back. Newer and older buttons are always there, placed every frame by the camera writer below the corners of the window in the middle of the screen: level with the labels on the timeline (labels are as tall as the 56px buttons, `TIMELINE_CONTROLS_GAP_PX` below the window), where they glide the row one window, and in the room below an open window, where they step to the neighbouring version (arrow keys too). Nothing fades in from nowhere: the controls hang from the bottom edge of the middle window, which is the screen's own edge while `crop` is 0, so they rise from below the screen as the time machine opens and sink back as it closes, and a sixth camera value, `open`, moves them into the room below an opened version. A step that has run out shrinks and fades away (`disabled:scale-50 opacity-0`, no pointer events) rather than dimming, and hands keyboard focus to the other arrow. The wheel does not snap, so while it leaves the row between windows (`isBetweenWindows`: over a screen px off one) both arrows go away the same way and turn inert, and come back when a glide starts or the row rests on a window again, since a step is from one window to the next; presses give under the finger (`active:scale-90`), on a CSS spring from `springCss`. On the timeline a window one click opens (wholly on screen, `isWindowInView`, or keyboard-focused) lifts under the pointer: a per-window `lifts` spring (`LIFT_SPRING`, quicker than the camera) grows it `LIFT_SCALE` about its centre and raises it `LIFT_PX`, folded into the camera writer's transforms (the present's canvas too) so opening carries on from the lifted pose, and a press gives it back to `PRESSED_LIFT`. It lights up as its 5% veil (`VEIL_OPACITY`; every timeline window has one) clears, a rim (its own squircle stroked twice as wide as it shows, inside the clip) fades in, its label brightens through `--lift`, and a `LiftShadow` drawn once at the timeline's zoom fades in under it. Veils are opacity layers rather than `filter: brightness()`, which would re-raster the live canvas each frame; the present's veil and rim sit in its click button, clipped per frame. Lifts are rechecked as the camera moves but held while the row is moving (camera faster than `SETTLED_SPEED_PX` or zooming, or within `SCROLL_SETTLE_MS` of a native scroll, whose jumps carry no velocity): sliding under a still pointer, each window rose and fell as it passed, as did a clicked cut-off window gliding in. The timeline has depth of field: `DepthOfField` stacks `DEPTH_LAYERS` of `backdrop-filter` blur on each side, from the screen's edge to the middle window's, under gradient masks so the blur grows outwards. A shader cannot do it: WebGPU/WebGL cannot read the live canvas or cross-origin frames, and backdrop filters can. The sides sit over windows and labels, under the step buttons, and the camera writer fades them with the timeline (`crop * (1 - open)`), hiding them once clear so nothing filters while a version is open. They blur only within `DEPTH_ZOOM_RANGE` (2%) of the timeline's zoom, and only over the band the row and its labels rest in (`DEPTH_BAND_MARGIN_PX` beyond it), in two layers: every backdrop px is redrawn each frame the row or the canvas under it moves, and at 5K (2560x1440 at 2x) the earlier full-height three-layer sides added about a dozen late frames to every zoom and every step-button glide. Now glides show none and a zoom one or two. The writer fades each layer, never their side: an opacity below 1 on the parent makes it the layers' backdrop root, so they blurred nothing until the fade ended (Safari showed the blur a second late). Each layer has `will-change: transform`: Chrome squashed the three overlapping masked backdrops into one layer and drew no blur at all, which only full-viewport screenshots show (a clipped screenshot recomposites and hides it; Playwright WebKit never draws backdrop filters in screenshots). In headed Chromium on an M3 at 2x, step-button glides showed no late frames with or without them; confirm Safari in Safari. The close button sits behind every window (`z-0`, above the backdrop alone), tucked `CLOSE_TUCK_PX` up behind the middle window's bottom edge, and slides out from under it with `open`, retreating behind it when the version shrinks back into the row. Stepping flies the camera straight to the neighbour, and `pushFrom` springs with it, so the window left behind eases aside instead of jumping to its pushed side. There is no history entry: frame navigations join the joint session history, so Back could not close it reliably. `e2e/time-machine.spec.ts` covers it (run it on one worker, as CI does: with parallel workers the lift test's hover sometimes lands while the row still counts as moving, and the veil stays at 5%); external origins are blocked in e2e, so frames there never load.

## Path aliases and TS config
- Prefer alias imports from `@/` for `src/*` modules.
- Alias is configured in both `vite.config.ts` and `tsconfig*.json`.
- TypeScript is strict; keep code compliant with:
  - `strict`, `noUnusedLocals`, `noUnusedParameters`
  - `noFallthroughCasesInSwitch`
  - `noUncheckedSideEffectImports`
  - `verbatimModuleSyntax`

## Formatting and linting rules
- Biome is the source of truth for formatting and linting.
- Do not introduce ESLint/Prettier-specific directives.
- Keep `noExcessiveCognitiveComplexity` disabled unless explicitly requested.
- VS Code settings expect Biome formatter + explicit organize/fix actions.
- Prefer small, local fixes over broad stylistic rewrites.

## Import conventions
- Import order: Node built-ins, third-party, `@/` aliases, then relative.
- Use `import type` for type-only imports.
- Keep imports organized (Biome can do this).
- Avoid default exports for components unless file already uses one.

## TypeScript conventions
- Prefer `interface` for component props and object contracts.
- Prefer `type` for unions, mapped helpers, and utility composition.
- Avoid `any`; use narrowed unions/generics instead.
- Keep shared domain types close to `src/types/*`.
- Use `as const` for static config/tuple literals.
- In `src/lib`, keep functions pure and DOM-free.

## React and hooks conventions
- Use function components with named exports.
- Keep render paths clear with guard clauses/early returns.
- Use `useMemo`/`useCallback` for expensive or identity-sensitive values.
- Use `useLayoutEffect` when logic depends on measured layout.
- Avoid inline handlers in hot render paths unless memoized.
- Co-locate local state unless it is truly shared (then use atoms).

## State and reducer conventions
- Treat reducer state as immutable.
- For `Map` and array updates, create new copies before writes.
- Return original state when an action is a true no-op.
- Keep action payloads typed; avoid stringly-typed loose payloads.
- Canvas state contracts live in `src/types/canvas.ts`.

## Styling conventions
- Tailwind utilities are primary; avoid ad-hoc CSS when utilities suffice.
- Use `tw(...)` helper from `src/lib/utils.ts` for class composition.
- Keep class strings readable and grouped logically.
- Prefer existing tokens (e.g., background/foreground token classes).
- Use inline style objects only for truly dynamic runtime values.

## Naming and file conventions
- Components: `PascalCase` identifiers.
- Hooks: `useXxx` naming.
- Files for components/hooks/utilities are typically kebab-case.
- Constants: `UPPER_SNAKE_CASE` for module-level constants, otherwise clear `camelCase`.
- Prefer descriptive prop and variable names over abbreviations.

## Error handling expectations
- Use guard clauses for invalid/missing state.
- Preserve behavior of `src/components/error-boundary.tsx`.
- Avoid silent failures; prefer explicit safe fallbacks.
- Add suppression comments (`biome-ignore`) only with a concise reason.

## Testing guidance
- Test files are colocated as `*.test.ts` / `*.test.tsx`.
- Prefer `@testing-library/react` for component behavior.
- Use helpers from `src/test-utils/test-helpers.tsx`.
- Current coverage thresholds (`vitest.config.ts`):
  - Statements: 80
  - Lines: 80
  - Branches: 65
  - Functions: 60
- Prefer behavior assertions over snapshots unless snapshot is clearly justified.

## Accessibility and UX guardrails
- Provide `aria-label` for icon-only buttons.
- Always set `type="button"` on non-submit button controls.
- Preserve keyboard navigation and focus-visible affordances.
- Keep semantic headings/labels intact during refactors.

## Performance guardrails
- Memoize heavy render branches/components when profiling supports it.
- Avoid repeated expensive calculations inside render.
- Use `requestAnimationFrame` for animation-driven updates.
- Use `ResizeObserver` for responsive measurement logic.

## Agent-specific workflow notes
- Make focused changes; avoid broad refactors unless asked.
- Match existing patterns before introducing new abstractions.
- Prefer updating existing files over creating parallel alternatives.
- If scripts/tooling change, update this file in the same PR.

## Commit messages
- Subject format: `type(scope): subject`, where type is one of `feat`, `fix`, `docs`, `perf`, `refactor`, `test`, `chore`, `style`, `build`, `ci`. Omit the scope only when no area fits (`feat: commit in-progress canvas work`).
- Scope names the area changed, in lowercase: `canvas`, `cards`, `writing`, `resume`, `about`, `swag`, `documents`, `deps`, `ui`.
- Subject is imperative, lowercase, has no trailing period, and stays under about 72 characters. Say what changed for a reader, e.g. `fix(canvas): keep auto-pan from overshooting fun cards`.
- Never use placeholder subjects such as `up`, `tweak`, `clean`, `Tests`, `Save uncommitted changes` or `WIP`. Read the diff and describe it.
- Body is optional. Use it for the why or a non-obvious tradeoff, as short wrapped bullets or sentences, not a file list.
- Do not add `Co-Authored-By` or any other attribution trailer, even when tooling suggests one.
